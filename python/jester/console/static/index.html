    run pipeline opens a dialog to pick the sources and an optional stop-at goal, then does the whole loop: fetch those sources with the Go worker, extract, archive and synthesize. ingest does the fetch half on its own; the pipeline still processes anything already queued. Fetching needs the Go toolchain and cloakserve on :9222 — those buttons appear once both are reachable.

    Sources

    The curated ingest list the live worker walks, grouped by platform — fold one shut to read the rest. Within a run the worker takes the least recently fetched first, so a depth ceiling spreads across the list instead of re-walking the top of it. Paste a subreddit, a thread, a YouTube channel or video, or a TikTok profile — anything the parser recognises.

    Search

    Ask the archive a question in your own words. Matches on meaning, not keywords — "backups fail silently" finds someone who wrote "my cron job dies without telling me".

    Clusters

    The archive regrouped by MEANING rather than by the thread each comment was scraped from — so the same complaint on Reddit and on Hacker News lands in one theme. Generate an idea from a theme, then save the ones worth keeping.

    Queue

    Scraped and waiting to be treated. Comments and listings are two different queues — different treatment, different budget — so they are counted apart.

    why is there a queue at all? Ingestion and treatment run on separate clocks by design: scraping is cheap and bounded by politeness, treatment is bounded by a token quota that resets on someone else's schedule. The gap is a standing state, not a moment between steps.

    Where it came from a queue that is mostly one platform is a skew about to be baked into the archive

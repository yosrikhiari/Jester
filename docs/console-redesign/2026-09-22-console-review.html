Eleven pages, 110 ways to make them better.

A page-by-page review of the Jester console after today's restyle, with ten sketched options per page. Every finding comes from the real app on the real archive (39 000 nuggets, 1 321 ideas, 115 sources), not from a mock.

How this was reviewed

  • Walked every page live at 1440 px and at the pane's narrow width, light and dark, with real data loading (2–3 s API waits included).
  • Read the renderer for each page in app.js (what it fetches, what it hides, what it never shows) and the API it calls.
  • Five lenses per page, scored 1–5: Clarity (can you tell what it's for in 3 s), Density (right amount on screen), Feedback (loading / success / error states), Speed (perceived), Action (is the next thing to do obvious).
  • Design rules applied: summary before detail; state encoded in form (pill, stripe) not only number; semantic color separate from the accent; repeated things composed as one object; nothing interactive that doesn't look interactive; no dead space, no clipped text.
  • Each option is a sketch — a wireframe, a title, and why. One per page is marked pick: what I would build first.

Twelve moves that lift the whole app

  1. Cache /api/infra for 30 sIt probes Ollama, cloakserve, Qdrant and Go on every page load — 3 s of blank. One cache kills most of the perceived slowness.
  2. Paginate or virtualise the big tablesNuggets renders 39 745 rows into the DOM. Ideas renders 1 321 with a <select> each. Both freeze the tab; screenshots time out.
  3. One "what is running now" strip in the top barRun id, phase, elapsed, a stop button — visible on every page, not only Overview. Today you learn a run exists by hunting.
  4. Sort actions by frequency, hide the restQuick actions is 10 buttons in one row; you use three. Primary, secondary, then an "…more" menu.
  5. Say why a number is what it is"0 / 0 kept / ideas" for 14 cycles in a row is the biggest fact on the Runs page and nothing explains it (it was the dedup outage + the Groq cap).
  6. Replace jargon with the user's words"unprocessed", "reembed backlog", "floor flags", "R41/R50" → "waiting for ideas", "not yet searchable", "run warnings".
  7. Empty and loading states with a next stepEvery empty state says what to do and links there: "No sources enabled → Add one".
  8. Detail in place, not far belowQueue opens a batch in a div under a 300-row table. Use the drawer pattern Ideas already has, everywhere.
  9. Trends, not just totalsNuggets, ideas and queue size over the last 7 days as a small sparkline next to the number. The archive is growing again today — the UI can't show that.
  10. Keyboard: / to search, r refresh, g o go overviewOnly r exists and it isn't discoverable. A "?" sheet lists them.
  11. Consistent status vocabularyproducing / quiet / barren, new / reviewed / building, pending / done / failed — three different families of pills with no shared color rule. One legend, one palette.
  12. The Posts pageThe plan's Reddit-watch library (plan §3-A) — the only new page; it should be born in the new system, not retrofitted.
